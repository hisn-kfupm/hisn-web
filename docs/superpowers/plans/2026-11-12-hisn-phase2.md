# حصن Phase 2 Implementation Plan

> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the hisn-sa.org teaser with the full phase 2 site (departments, calendar, registration with waitlist, emails, library, قاعدة المواهب, admin) by Wed 25 Nov 2026, hard deadline Tue 1 Dec.

**Architecture:** One Next.js app on Vercel. All writes go through server actions or route handlers. Production data in `hisn-prod` and talent data in `hisn-talent`, each in an owner-only Supabase organization; developers work only against `hisn-dev` and throwaway CI databases. Emails go through an outbox table and Resend.

**Tech Stack:** Next.js (App Router) + TypeScript, Supabase (Postgres, Auth, CLI, pgTAP), Tailwind CSS, Zod, Resend + React Email, Sentry, Vitest, Playwright, GitHub Actions, Vercel Pro (+ Cron).

**Spec:** `docs/superpowers/specs/2026-11-10-hisn-phase2-design.md` (revision 2). Section numbers below (§) refer to it.

## Global Constraints

- P-1: when protection and convenience conflict, protection wins (§3).
- HR-1: developers can never read talent data. `supabaseTalent` lives only in `lib/db/talent.ts`, importable only from `app/talent/actions.ts`; inserts request no returned row; never add a read policy.
- HR-2: the talent form never asks for email, Arabic name, major, academic level or gender; the server copies them from the profile.
- HR-4: no code path writes `profiles.is_admin`.
- HR-5: signed links act only on POST; GET renders a confirm page.
- HR-7: no literal UI text in components (keys into `lib/i18n/ar.json`); no physical `left`/`right` CSS.
- HR-8: the talent form opens only when `TALENT_FORM_OPEN=true`, set only with final consent text.
- Banned identifier: `supabase`. Use `supabaseProd` / `supabaseTalent`.
- Times stored UTC, displayed `Asia/Riyadh`. Mixed-direction values inside Arabic text wrapped in `<bdi>`.
- Sign-in: 6-digit OTP, 10-minute expiry, resend after 60 s.
- `ALMOST_FULL_RATIO = 0.2`; almost full when `0 < seatsLeft ≤ max(1, floor(capacity × 0.2))`.
- Announcement batches ≤ 100; idempotency key `{kind}-event-{id}-run-{r}-batch-{n}`.
- Cron `/api/cron/flush-email` every 10 minutes; sends rows `queued` for > 2 minutes.
- CSV exports start with a UTF-8 BOM and use data-file labels, not codes.
- Data-file codes are append-only after launch; migrations' allowed codes must equal the files.
- Production migrations are expand-only.
- Contact address: `Contact@Hisn-sa.org`. Sender: `حصن <noreply@hisn-sa.org>`.
- Founder's announcements copy, verbatim: «لقاءات مع قادة القطاع، وورش تقرّبك من دورك فيه، تصلك أولًا بأول على بريدك.»
- Almost-full badge copy, verbatim: «المقاعد شارفت على الاكتمال!»

**TDD rule for every task:** write the tests named in the task first, run them and see them fail, implement, run them and see them pass, commit. The task lists the tests and the verification command; it does not repeat these four steps.

## Review Focus

1. **Arabic text containing an email, URL or English name** renders in the wrong order (`ali@gmail.com.` jumps to the start of the line). Expected: correct order everywhere. Test in Task 8 (`Bdi` component) and Task 14 (email templates).
2. **An event late in the evening Riyadh time** (e.g. 23:30 on the last day of a month) appears on the wrong calendar day or month because UTC is already the next day. Expected: Riyadh date. Test in Task 10.
3. **A slow phone connection with repeated taps** on register, join waitlist or send announcement creates duplicates. Expected: one outcome; buttons disabled while pending. Tests in Task 13 and Task 18.
4. **A promoted waitlisted person never learns they got a seat** because the server failed after the database commit. Expected: the queued email is still sent by the cron. Test in Task 14.
5. **A crafted `returnTo` after sign-in** (`//evil.com`, `https://evil.com`) redirects off-site. Expected: falls back to `/`. Test in Task 6.
